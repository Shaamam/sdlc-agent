# Phase 7 — Pull request

Goal: a PR a reviewer can approve without opening Jira.

1. Bring the branch up to date without rewriting pushed history:
   ```
   git fetch origin {base}
   git merge --no-edit origin/{base}
   ```
   On conflicts, resolve them in line with the spec, re-run tests and lint, and commit. If a conflict is in code you don't understand, stop and ask the developer.

2. Push the feature branch, never the base, never force:
   `git push -u origin {branch}`

3. Write the PR body to `{TDIR}/pr-body.md` from `{SKILL_DIR}/references/templates/pr-body.md`. Get the Jira site from the `self` URL in `ticket.json`, so the link is `https://<site>/browse/{KEY}`.

4. Create it, or update it if one already exists for the branch:
   ```
   gh pr list --head {branch} --json number,url --state open
   gh pr create --base {base} --head {branch} --title "{KEY}: <summary>" --body-file "{TDIR}/pr-body.md"
   # existing PR: gh pr edit <number> --body-file "{TDIR}/pr-body.md"
   ```
   Don't add reviewers or labels unless the repo config or the developer says so.

5. Record:
   `{STATE} set {KEY} pr.number=<n> pr.url="<url>"`
   `{STATE} event {KEY} pr_opened --data '{"number": <n>, "url": "<url>"}'`

6. If `jira.in_review_status` is set:
   `acli jira workitem transition --key {KEY} --status "<in_review_status>" --yes`
   Then comment the PR link: `acli jira workitem comment create --key {KEY} --body "PR opened: <url>"`

7. Next: `{STATE} phase {KEY} ci` and read `08-ci.md`.
